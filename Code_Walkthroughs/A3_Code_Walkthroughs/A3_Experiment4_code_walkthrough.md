## Key background: two ways to take a gradient step

- **SGD with momentum** keeps a running velocity: `v ← 0.9·v + g`, then `w ← w − lr·v`.
  Momentum smooths noisy mini-batch gradients and speeds movement along consistent
  directions. Every parameter uses the same step size.
- **Adam** keeps running averages of the gradient *and* of its square, and divides one by the
  square root of the other. Each parameter effectively gets its own step size, roughly
  normalized to the gradient's typical magnitude. It is less sensitive to the raw learning
  rate, which is why its conventional default is smaller.

Because the two scale steps so differently, "the same learning rate" is not a fair control.
The harness pairs each optimizer with its own conventional rate for the training mode:
for a frozen head, **SGD `1e-2`** and **Adam `1e-3`**. What Experiment 4 compares is therefore
two *recipes* — optimizer plus its standard rate — under everything else held equal.

## Two concepts examiners love to probe

1. **Is this an optimizer comparison or a learning-rate comparison?** Both, unavoidably. The
   two optimizers use different conventional rates, so the result says which *recipe*
   converged faster, not that SGD is intrinsically better. Separating them would need a sweep
   of rates for each optimizer.
2. **Why read loss curves when accuracy is already 100 %?** Accuracy only checks whether the
   right class has the largest score. Loss also measures *how confident* the correct score is.
   Two models at 100 % accuracy can differ a lot in loss, and loss keeps showing progress after
   accuracy has saturated — which is why it is the tie-break here.
