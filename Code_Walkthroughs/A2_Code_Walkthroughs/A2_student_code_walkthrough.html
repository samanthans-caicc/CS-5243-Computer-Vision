CROSS-CUTTING

Four rules the whole file obeys

Every function is a variation on the same commitments. Once you see them, the file stops being thirteen separate problems.

Rule 01

float32 in, float32 out, never the caller's array

_check_image converts every input to a fresh float32 array up front. Every return path is a new allocation or an explicit .copy(). Nothing is ever written through to the image the caller passed.

Rule 02

Validate with not (x > 0), not x <= 0

The negated-positive form also rejects NaN. Odd sizes, positive sigmas, probabilities in [0,1], percentile order, positive level counts — all checked before anything is allocated, all raising ValueError.

Rule 03

Loop over taps, never over pixels

Convolution and median both walk the kernel offsets and apply each one to a whole shifted slice of the padded image. The channel axis rides along in the slice, so 2-D and HxWxC share one code path.

Rule 04

Shapes are recorded, not recomputed

Ceiling-halving is not invertible by doubling (33 · 2 ≠ 65). Every pyramid level carries its own shape, and expand_image is always told exactly what to produce.

01

Three helpers everything else leans on

Padding, coercion, and the odd-size check — written once, used by six functions.

student_code.py:11–36 · _pad_spatial, _check_image, _check_odd_size

_PAD_MODES = {"reflect": "reflect", "edge": "edge", "constant": "constant"}

def _pad_spatial(image, radius, border_mode):
    if border_mode not in _PAD_MODES: raise ValueError(...)
    pad = [(radius, radius), (radius, radius)] + [(0, 0)] * (image.ndim - 2)
    if border_mode == "constant":
        return np.pad(image, pad, mode="constant", constant_values=0)
    return np.pad(image, pad, mode=_PAD_MODES[border_mode])

def _check_image(image):
    a = np.asarray(image, dtype=np.float32)
    if a.ndim not in (2, 3): raise ValueError(...)
    return a

def _check_odd_size(size, name="kernel size"):
    if not isinstance(size, (int, np.integer)) or isinstance(size, bool):
        raise ValueError(...)
    if size <= 0 or size % 2 == 0: raise ValueError(...)
    return int(size)

_pad_spatial pads only the first two axes. The [(0, 0)] * (ndim - 2) term appends a no-op pad for the channel axis when there is one, which is the entire reason the filters below never need a per-channel branch.

The three names map onto the README's contract exactly: NumPy reflect is OpenCV BORDER_REFLECT_101 (mirror without repeating the edge pixel), edge is BORDER_REPLICATE, constant is zero. The notebook uses the same mapping when it calls cv2.filter2D, which is what makes the reference errors land at 1e-7 instead of 0.1 at the frame.

Why the bool check

True is an int in Python, and True % 2 == 1. Without isinstance(size, bool), gaussian_kernel(True, 1.0) would quietly build a 1×1 kernel.

02

True convolution, and a kernel to feed it

One reversed index is the difference between convolution and correlation. The asymmetric-kernel experiment exists to prove it is there.

student_code.py:39–69 · convolve2d_manual

img = _check_image(image)
k = np.asarray(kernel, dtype=np.float32)
kh, kw = k.shape                       # both validated odd
rh, rw = kh // 2, kw // 2
radius = max(rh, rw)
padded = _pad_spatial(img, radius, border_mode)
H, W = img.shape[:2]
flipped = k[::-1, ::-1]                # true convolution
out = np.zeros(img.shape, dtype=np.float32)
for i in range(kh):
    for j in range(kw):
        w = flipped[i, j]
        if w == 0:
            continue
        y0 = radius - rh + i
        x0 = radius - rw + j
        out += w * padded[y0:y0 + H, x0:x0 + W]
return out.astype(np.float32)

Convolution is defined with the kernel rotated 180°: out[y,x] = Σ k[i,j] · img[y−i+r, x−j+r]. Correlation lays it down as-is. k[::-1, ::-1] is the rotation; after it, each tap of flipped multiplies a whole H×W slice of the padded image shifted by that tap's offset, and the slices are summed.

The loop runs k² times, not H·W times. A 25×25 kernel on the 255×383 test pattern is 625 vectorized multiply-adds — about 10 ms — with no call into cv2.filter2D or scipy.signal.

y0 = radius − rh + i handles non-square kernels: the pad is by the larger half-size, and the smaller axis starts partway in.

The evidence

Against cv2.filter2D on the flipped kernel: 6e-8. Against filter2D on the unflipped kernel: 0.51. Same code, same border, one index reversed. A symmetric Gaussian could never expose the difference.

student_code.py:72–87 · gaussian_kernel, gaussian_support

def gaussian_kernel(size, sigma):
    size = _check_odd_size(size, "size")
    if not (sigma > 0): raise ValueError(...)
    r = size // 2
    ax = np.arange(-r, r + 1, dtype=np.float64)
    g1 = np.exp(-(ax ** 2) / (2.0 * float(sigma) ** 2))
    k = np.outer(g1, g1)
    k /= k.sum()
    return k.astype(np.float32)

def gaussian_support(sigma):
    return max(3, 2 * int(math.ceil(3.0 * sigma)) + 1)

A 2-D Gaussian is separable — G(x,y) = g(x)·g(y) — so np.outer of one 1-D profile is the whole kernel, and it is symmetric by construction (k == k[::-1, ::-1], which the public test asserts).

Normalizing by k.sum() rather than the analytic 2πσ² makes the truncated kernel sum to exactly one, so a flat region stays flat. Built in float64, cast once at the end.

gaussian_support is the stated support convention: ±3σ (99.7 % of the mass), forced odd, never below 3. σ = 1.5 → 11, σ = 2 → 13, σ = 3 → 19. Exposing it lets the notebook write the size into every metrics row.

student_code.py:90–103 · sharpen_image

Unsharp masking, literally: img − blur is the high-pass detail; add it back scaled by amount. amount = 0 is the identity to the bit, and the output is exactly linear in amount — the notebook checks sharpen(2a) − x == 2·(sharpen(a) − x) to 1.8e-7.

No clipping. Overshoot past [0, 1] is the halo, and it is evidence — Task 7's first failure is this function at amount = 6, max value 3.7.

03

Two noise models, one generator

Every random number comes from the Generator the caller supplies. Same seed, same image, any machine.

student_code.py:106–133 · add_gaussian_noise, add_impulse_noise

def add_gaussian_noise(image, sigma, rng):
    if not (sigma >= 0): raise ValueError(...)
    img = _check_image(image)
    noise = rng.normal(0.0, float(sigma), size=img.shape).astype(np.float32)
    return np.clip(img + noise, 0.0, 1.0).astype(np.float32)

def add_impulse_noise(image, probability, rng):
    if not (0.0 <= probability <= 1.0): raise ValueError(...)
    img = _check_image(image)
    H, W = img.shape[:2]
    selected = rng.random((H, W)) < probability
    salt = rng.random((H, W)) < 0.5
    values = np.where(salt, np.float32(1.0), np.float32(0.0))
    out = img.copy()
    if img.ndim == 3:
        out[selected] = values[selected][:, None]
    else:
        out[selected] = values[selected]
    return out.astype(np.float32)

Gaussian noise is drawn with the image's full shape — independent per channel, the usual sensor model — then clipped, because a normalized image cannot hold −0.05.

Impulse noise draws two (H, W) arrays, not (H, W, C): selection is per pixel, and a selected colour pixel gets the same value on every channel. values[selected][:, None] is the broadcast that copies one value across the (n, C) slice.

Why two draws

random() < p selects each pixel independently with probability exactly p; a second random() < 0.5 chooses salt or pepper with equal odds. At p = 1.0 every pixel is hit, which is the public test's {0.0, 1.0} check.

student_code.py:136–150 · median_filter_manual

k = _check_odd_size(kernel_size, "kernel_size")
img = _check_image(image)
r = k // 2
padded = _pad_spatial(img, r, border_mode)
H, W = img.shape[:2]
stack = np.empty((k * k,) + img.shape, dtype=np.float32)
idx = 0
for i in range(k):
    for j in range(k):
        stack[idx] = padded[i:i + H, j:j + W]
        idx += 1
return np.median(stack, axis=0).astype(np.float32)

The same tap-walking loop as the convolution, but instead of weighting and summing the shifted slices it stacks them on a new leading axis. stack[:, y, x] is then pixel (y, x)'s whole neighbourhood, and np.median(axis=0) takes the middle value of each.

np.median is a reduction, not a filter — the windowing, padding, and border rule are all here. Memory is k²·H·W·4 bytes: ~19 MB for k = 7 on the test pattern.

04

Moving tones: stretch, equalize, gamma

Three monotone remaps with three different costs — clipping, noise amplification, colour shift.

student_code.py:153–166 · normalize_contrast

if not (0.0 <= low_percentile < high_percentile <= 100.0): raise ValueError(...)
img = _check_image(image)
lo, hi = np.percentile(img.astype(np.float64), [low_percentile, high_percentile])
if hi == lo: raise ValueError(...)
out = (img.astype(np.float64) - lo) / (hi - lo)
return np.clip(out, 0.0, 1.0).astype(np.float32)

np.percentile over the whole array — every pixel, every channel, together. One lo, one hi, one affine map for all channels. A per-channel stretch would be a colour cast; this preserves channel ratios.

The chained comparison is the README's 0 ≤ low < high ≤ 100 in one line. hi == lo — a flat image, or two percentiles landing on the same quantized value — would divide by zero, so it raises.

student_code.py:169–186 · histogram_equalize_gray

a = np.asarray(image)
if a.ndim != 2 or a.dtype != np.uint8: raise ValueError(...)
hist = np.bincount(a.ravel(), minlength=256).astype(np.float64)
cdf = np.cumsum(hist)
cdf_min = cdf[np.nonzero(cdf)[0][0]]
total = cdf[-1]
if total == cdf_min:
    return a.copy()
lut = np.rint((cdf - cdf_min) / (total - cdf_min) * 255.0)
lut = np.clip(lut, 0, 255).astype(np.uint8)
return lut[a]

np.bincount(minlength=256) is the exact 256-bin histogram of a uint8 image with no binning to get wrong. The CDF is its running sum.

The classic map T(v) = rint((cdf(v) − cdf_min) / (N − cdf_min) · 255): subtracting the first nonzero CDF value pins the darkest occupied level to 0 and the brightest to 255, so the full range is used. np.rint is round-half-to-even, as the README requires.

A single grey level gives total == cdf_min and a 0/0; the contract says return the image unchanged, so it does — as a copy.

lut[a]

Build the 256-entry table once, then apply it to every pixel with one fancy-index. No per-pixel loop, and the same LUT idea the notebook uses to equalize luma and then scale colour channels by the resulting gain.

student_code.py:189–197 · apply_gamma

if not (gamma > 0): raise ValueError(...)
img = np.clip(_check_image(image), 0.0, 1.0)
return np.power(img, np.float32(gamma)).astype(np.float32)

Clip first, then x^γ. On [0, 1] the power stays in [0, 1] for any positive γ, so nothing needs clipping afterwards. γ < 1 lifts every value toward 1 (brightens), γ > 1 pushes toward 0 (darkens), γ = 1 is the identity — the three cases the public test checks.

Measured on exposure_under.png: γ = 0.5 lifts the luma mean from 0.15 to 0.37 with zero clipping and only 1.25× noise amplification — the gentlest of the three tone methods on both counts.

05

Pyramids: reduce, expand, subtract, add back

cv2.pyrDown and cv2.pyrUp are the approved one-step primitives. Everything that makes them a pyramid is here.

student_code.py:202–222 · _restore_channels, reduce_image, expand_image

def reduce_image(image):
    img = _check_image(image)
    H, W = img.shape[:2]
    out = cv2.pyrDown(img, dstsize=((W + 1) // 2, (H + 1) // 2))
    return _restore_channels(out, img).astype(np.float32)

def expand_image(image, target_shape):
    img = _check_image(image)
    H, W = int(target_shape[0]), int(target_shape[1])
    out = cv2.pyrUp(img, dstsize=(W, H))
    return _restore_channels(out, img).astype(np.float32)

Both pass dstsize explicitly. pyrDown's default already ceiling-halves, but writing (W + 1) // 2 makes the contract visible. pyrUp has no way to guess 65 from 33, so the target shape is mandatory — it accepts anything within ±2 of double, which is exactly what ceiling-halving needs.

OpenCV's Size is (width, height), NumPy's shape is (height, width). The swap happens in these two helpers and nowhere else.

_restore_channels puts back a trailing singleton channel axis if OpenCV dropped one ((H, W, 1) in → (H, W) out). RGB and grayscale never hit it.

student_code.py:231–260 · gaussian_pyramid, laplacian_pyramid, reconstruct_laplacian_pyramid

def gaussian_pyramid(image, levels):
    levels = _check_levels(levels)
    current = _check_image(image)
    pyramid = [current]
    for _ in range(levels - 1):
        current = reduce_image(current)
        pyramid.append(current)
    return pyramid

def laplacian_pyramid(image, levels):
    gauss = gaussian_pyramid(image, levels)
    pyramid = []
    for finer, coarser in zip(gauss[:-1], gauss[1:]):
        pyramid.append((finer - expand_image(coarser, finer.shape)).astype(np.float32))
    pyramid.append(gauss[-1])
    return pyramid

def reconstruct_laplacian_pyramid(pyramid):
    current = np.asarray(pyramid[-1], dtype=np.float32)
    for level in reversed(pyramid[:-1]):
        current = (expand_image(current, level.shape) + level).astype(np.float32)
    return current

Exactly levels arrays, finest first. zip(gauss[:-1], gauss[1:]) pairs each level with the next-coarser one; L_i = G_i − expand(G_{i+1}) is the band-pass residual, and the coarsest Gaussian goes on the end unchanged — the Burt–Adelson layout.

expand_image(coarser, finer.shape) is where odd sizes are handled. The expansion is told to produce finer's exact shape, so the subtraction always lines up; the reconstruction reads each level's shape back the same way. No arithmetic on sizes anywhere.

The evidence

Max reconstruction error 1.5e-8 on color_scene.png (257×385×3) and 6e-8 on the 255×383 grayscale pattern, for levels 2 through 6. That is one float32 ulp at 1.0 — the decomposition is exactly invertible at every odd/even transition.

06

Blending per band

Three pyramids, one loop, one reconstruction. The mask gets a Gaussian pyramid, not a Laplacian one.

student_code.py:263–286 · laplacian_pyramid_blend

a = _check_image(image_a)
b = _check_image(image_b)
m = np.asarray(mask, dtype=np.float32)
if a.shape != b.shape:            raise ValueError(...)
if m.shape[:2] != a.shape[:2]:    raise ValueError(...)
if m.ndim == 3 and m.shape[2] == 1: m = m[..., 0]
if m.ndim != 2:                   raise ValueError(...)

lap_a   = laplacian_pyramid(a, levels)
lap_b   = laplacian_pyramid(b, levels)
gauss_m = gaussian_pyramid(m, levels)
blended = []
for la, lb, gm in zip(lap_a, lap_b, gauss_m):
    weight = gm[..., None] if la.ndim == 3 else gm
    blended.append(((1.0 - weight) * la + weight * lb).astype(np.float32))
return reconstruct_laplacian_pyramid(blended)

The same (1 − w)·a + w·b as direct blending, applied at every level with w taken from the mask's Gaussian pyramid. Because the mask is blurred and halved along with the images, coarse bands (colour) cross-fade over a wide transition and fine bands (texture) over a narrow one — the transition width scales with content automatically.

gm[..., None] gives the (h, w) mask level a channel axis so it broadcasts against an (h, w, 3) image level; the conditional keeps grayscale blends working.

"Mask 0 selects image_a" falls out algebraically: a zero mask has a zero Gaussian pyramid, blended == lap_a, and reconstruction returns a to 1e-5 (the public test).

Why the mask gets a Gaussian pyramid

The mask is a weight, not a signal. Each level needs the full low-passed weight; a Laplacian mask level is near zero almost everywhere and would select neither image.

08

Sharp edges

Nothing here fails the public tests. These are the places where a future edit could go wrong, or where the code makes a choice worth being able to defend.

Median memory grows with k²median_filter_manual:144

The stacked-slices approach allocates k²·H·W·4 bytes. Fine for the assignment's 255×383 images and k ≤ 7 (~19 MB); a 4K frame at k = 15 would be ~7 GB. A running-histogram median is the fix if that ever matters.

Sharpening border is fixed to reflectsharpen_image:102

The unsharp blur always uses "reflect"; the caller cannot choose. That is a deliberate simplification of the contract, and it is the mode under which edge behaviour at the frame is least distorted — but it is not a parameter, and the docstring does not say so.

Percentiles of a quantized image are step functionsnormalize_contrast:164

On the 8-bit exposure_under.png, the 1st and 2nd percentiles land on the same value, so normalize_contrast(img, 1, 99) and (img, 2, 98) are bit-identical. Correct behaviour, but a surprise if you expect different percentiles to always give different outputs — and the reason the hi == lo guard exists.

Blend output is not clippedlaplacian_pyramid_blend:284

A blend of two [0, 1] images stays in [0, 1] mathematically, but pyrUp/pyrDown rounding can leave values at 1.0000001 or −1e-8. Harmless, and the notebook clips for display — but anything that casts straight to uint8 should clip first.

Mask tolerance is asymmetriclaplacian_pyramid_blend:270–274

An (H, W, 1) mask is squeezed and accepted; an (H, W, 3) mask is rejected. A per-channel mask is a legitimate thing to want, but the contract says "spatial mask," so the function stays strict rather than guessing which channel to use.
