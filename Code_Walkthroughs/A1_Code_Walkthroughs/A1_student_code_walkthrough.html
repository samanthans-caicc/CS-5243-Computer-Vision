CROSS-CUTTING

Four rules the whole file obeys

Every function here is a variation on the same four commitments. Once you see them, the file stops being fifteen separate problems.

Rule 01

The caller's array is never touched

Every return path ends in .copy() or a freshly allocated array. Slicing NumPy gives you a view — writing through it would silently edit the original image.

Rule 02

Validate first, then act

_check_rectangle, _check_uint8, _check_rgb. Nothing is allocated until the inputs are known good, so a bad call raises ValueError instead of producing a quietly wrong image.

Rule 03

Round, then clip, then cast

In that order, always. np.rint is round-half-to-even; clipping before the uint8 cast is what stops 260 from wrapping around to 4.

Rule 04

The dtype sets the scale

Normalization divides by np.iinfo(dtype).max, never by the brightest pixel present. The same stored value maps to the same float in every image.

01

Describing an image

One function, and it has to answer for both layouts an image can arrive in.

student_code.py:10–29 · image_summary

arr = np.asarray(image)
if arr.ndim == 2:                       # grayscale: no channel axis
    height, width = arr.shape
    channels = 1
elif arr.ndim == 3:                     # color: (H, W, C) with C == 3 or 4
    height, width, channels = arr.shape
else:
    raise ValueError(...)
return {
    "shape": tuple(int(n) for n in arr.shape),
    "height": int(height), "width": int(width),
    "channels": int(channels),
    "dtype": str(arr.dtype),
    "range": (arr.min().item(), arr.max().item()),
    "mean": float(arr.mean()),
    "nbytes": int(arr.nbytes),
}

A grayscale image is (H, W) — two axes, no channel axis at all. A color image is (H, W, C). The branch exists because "channels" is not a stored property of a grayscale array; the value 1 is a convention this function imposes so the metadata table has a column that is always filled.

The exit is deliberately made of Python scalars: int(), float(), str(), and .item() on the min/max. NumPy scalars would serialize into the CSV as np.uint8(0) instead of 0.

Worth knowing

arr.mean() on a uint8 array accumulates in float64, so a bright 4K image will not overflow the sum. That is NumPy's choice, not an accident of this code.

02

Indexing: crops, flips, channels

Five functions, one shared guard, and a single idea — slice, then copy.

student_code.py:32–46 · _check_rectangle, crop_image

def _check_rectangle(image, top, left, height, width):
    if min(int(top), int(left)) < 0 or min(int(height), int(width)) <= 0:
        raise ValueError(...)
    if top + height > image.shape[0] or left + width > image.shape[1]:
        raise ValueError(...)

def crop_image(image, top, left, height, width):
    arr = np.asarray(image)
    _check_rectangle(arr, top, left, height, width)
    return arr[top:top + height, left:left + width].copy()

The guard encodes the assignment's contract exactly: origin at or above zero, size strictly positive, far edge inside the image. Note the asymmetry — a zero origin is legal, a zero size is not, which is why one comparison is < 0 and the other <= 0.

The guard is doing real work that plain slicing cannot. Python happily accepts arr[5:2] and arr[0:9999], returning an empty or truncated array with no complaint. Silent wrong shapes are worse than an exception.

Why .copy()

arr[a:b, c:d] is a view into the caller's memory. Return it raw and a later crop[:] = 0 would blank out part of the original image. The copy costs one allocation and buys independence — Rule 01.

student_code.py:49–69 · flip_horizontal, extract_channel, bgr_to_rgb

def flip_horizontal(image):
    return np.asarray(image)[:, ::-1].copy()

def extract_channel(image, channel):
    arr = np.asarray(image)
    if arr.ndim != 3: raise ValueError(...)
    if not 0 <= channel < arr.shape[2]: raise ValueError(...)
    return arr[:, :, channel].copy()

def bgr_to_rgb(image):
    arr = np.asarray(image)
    if arr.ndim != 3 or arr.shape[2] != 3: raise ValueError(...)
    return arr[:, :, ::-1].copy()

Three one-liners that differ only in which axis gets the reversed stride. [:, ::-1] reverses columns — a mirror. [:, :, ::-1] reverses the channel axis — BGR becomes RGB. Same operator, completely different meaning, decided entirely by position.

index 0 — B index 1 — G index 2 — R

Reversed becomes R, G, B. This is the conversion you need every time OpenCV hands an array to Matplotlib, because cv2.imread returns BGR and plt.imshow assumes RGB.

extract_channel uses 0 <= channel < shape[2] rather than letting NumPy index. Without it, channel = -1 would quietly return the last channel — a plausible-looking result from a bug.

student_code.py:72–79 · replace_region

arr = np.asarray(image)
_check_rectangle(arr, top, left, height, width)
out = arr.copy()
out[top:top + height, left:left + width] = value
return out

The mirror image of crop_image, and it reuses the same guard — the rectangle contract is written once and enforced in both places.

Here the copy comes first: copy the whole image, then mutate the copy. That is what makes an in-place-looking operation non-destructive.

value can be a scalar or a 3-element sequence, and broadcasting handles both without a branch. A single 0 fills every channel; [255, 0, 0] paints red across the rectangle.

03

Packing the contact sheet

The only function in the file with real geometry in it.

student_code.py:82–112 · contact_sheet

is_rgb = items[0].ndim == 3
for im in items:
    if im.dtype != np.uint8: raise ValueError(...)
    ok = (im.ndim == 3 and im.shape[2] == 3) if is_rgb else (im.ndim == 2)
    if not ok: raise ValueError(...)

border = gutter = 8
cell_h = max(im.shape[0] for im in items)
cell_w = max(im.shape[1] for im in items)
rows = (len(items) + columns - 1) // columns
height = 2 * border + rows * cell_h + (rows - 1) * gutter
width  = 2 * border + columns * cell_w + (columns - 1) * gutter
sheet = np.full(shape, fill_value, dtype=np.uint8)

for idx, im in enumerate(items):
    r, c = divmod(idx, columns)
    y0 = border + r * (cell_h + gutter)
    x0 = border + c * (cell_w + gutter)
    sheet[y0:y0 + im.shape[0], x0:x0 + im.shape[1]] = im

The first image decides the mode — grayscale or RGB — and every other image must agree. Mixing them is rejected rather than coerced, because there is no correct silent answer to "paste a 2-D image into a 3-channel sheet."

The cell is sized to the largest image, so every cell is identical and the grid stays rectangular. Smaller images sit at the top-left of their cell and the leftover area keeps the fill color.

Two small arithmetic details carry the layout:

(len + columns - 1) // columns is integer ceiling division — 7 images in 3 columns needs 3 rows, not 2.

(rows - 1) * gutter, not rows * gutter — gutters live between cells, so n cells have n−1 gaps. The outer edge is the border's job.

divmod(idx, columns) converts a flat index into a (row, column) pair in one call — the standard way to walk a grid stored as a list.

04

Brightness, twice — and the tie-break that makes them agree

The point of writing the same operation two ways is the timing comparison. The point of writing them carefully is that the outputs must be bit-identical.

student_code.py:123–144 · brighten_loop, brighten_vectorized

def brighten_loop(image, offset):
    arr = _check_uint8(image)
    shift = float(offset)
    source = arr.reshape(-1)         # one flat loop covers 2-D and 3-D alike
    result = np.empty(source.size, dtype=np.uint8)
    for i in range(source.size):
        value = float(np.rint(float(source[i]) + shift))
        if value < 0.0:     value = 0.0
        elif value > 255.0: value = 255.0
        result[i] = value
    return result.reshape(arr.shape)

def brighten_vectorized(image, offset):
    arr = _check_uint8(image)
    shifted = arr.astype(np.float64) + float(offset)
    return np.clip(np.rint(shifted), 0.0, 255.0).astype(np.uint8)

reshape(-1) flattens to 1-D so a single loop handles grayscale and color alike, and the final reshape(arr.shape) restores the original layout. No nested loops, no separate 2-D/3-D code paths.

Why uint8 + offset cannot be done directly: NumPy would wrap. 200 + 100 in uint8 is 44, not 255. Both functions escape to floating point first, which is what makes clipping meaningful.

The tie-break

np.rint is round-half-to-even: 0.5 → 0, 1.5 → 2, 2.5 → 2. It is used in both functions, and both compute in a Python float/float64. That is the reason outputs_equal in timing.csv comes out True for a half-integer offset such as 12.5 — a loop using Python's int(x + 0.5) would round half-up and disagree with the vectorized path on exactly those pixels.

The clipping is spelled out as if/elif in the loop and np.clip in the vectorized version. Same three-step order in both — round, clip, cast.

05

Crossing between dtypes

Two functions that have to be exact inverses on the round trip.

student_code.py:147–165 · to_float01, to_uint8_safe

def to_float01(image):
    arr = np.asarray(image)
    if arr.dtype not in (np.uint8, np.uint16):
        raise ValueError(...)
    return (arr.astype(np.float32)
            / np.float32(np.iinfo(arr.dtype).max)).astype(np.float32)

def to_uint8_safe(image):
    arr = np.asarray(image)
    if arr.dtype.kind != "f":
        raise ValueError(...)
    scaled = np.clip(arr.astype(np.float64), 0.0, 1.0) * 255.0
    return np.rint(scaled).astype(np.uint8)

Divide by the dtype's maximum, not the image's. np.iinfo(uint8).max is 255 and np.iinfo(uint16).max is 65535 — properties of the representation. Normalizing by arr.max() instead would make a dim photograph and a bright one map to the same float range, destroying exactly the intensity information the experiment is measuring.

dtype.kind != "f" catches float16, float32 and float64 in one test, instead of listing them.

Clip before scale, round in float64

Clipping to [0, 1] before multiplying means an out-of-range 1.2 saturates to 255 rather than becoming 306 and wrapping to 50 on the cast. And doing it in float64 is what makes the round trip exact: k/255 is not representable in binary, and in float32 the accumulated error can land a value a hair below k + 0.5 where float64 lands it on k.

Note the asymmetry between the two: to_float01 works in float32 because that is the dtype the assignment asks it to produce, while to_uint8_safe promotes to float64 because it only needs precision, not a dtype.

06

Color: two grays and a circular hue

Where the code stops being about arrays and starts being about how people see.

student_code.py:176–187 · grayscale_mean, grayscale_luminance

def grayscale_mean(image_rgb):
    arr = _check_rgb(image_rgb)
    return arr.astype(np.float32).mean(axis=2, dtype=np.float32)

def grayscale_luminance(image_rgb):
    arr = _check_rgb(image_rgb).astype(np.float32)
    weights = np.array([0.299, 0.587, 0.114], dtype=np.float32)   # ITU-R BT.601
    return (arr @ weights).astype(np.float32)

Two answers to "make this gray," and the difference between them is the whole point of the experiment.

grayscale_mean treats the channels as equally important. grayscale_luminance weights them by how strongly human vision responds:

R · 0.299 G · 0.587 B · 0.114

Green carries nearly 60% of perceived brightness and blue barely a tenth. A saturated blue region comes out far darker under BT.601 than under a flat mean — which is what you will see when you diff the two output figures.

arr @ weights is a matrix product contracting the last axis: an (H, W, 3) array against a (3,) vector gives (H, W). One operator replaces three multiplies and two adds.

Why float32 everywhere

The functions never rescale, so whatever the caller passes — 0–255 or 0–1 — comes back on the same scale. mean(axis=2, dtype=np.float32) pins the accumulator explicitly instead of letting NumPy pick.

student_code.py:190–207 · hsv_rule

hue, sat, val = (arr[:, :, i].astype(np.int32) for i in range(3))

mask = (sat >= low[1]) & (sat <= high[1]) \
     & (val >= low[2]) & (val <= high[2])

if low[0] <= high[0]:
    hue_mask = (hue >= low[0]) & (hue <= high[0])
else:
    # OpenCV hue is 0-179 and circular: lower > upper crosses 0
    hue_mask = (hue >= low[0]) | (hue <= high[0])
return mask & hue_mask

Saturation and value are ordinary intervals. Hue is not — it is an angle, and OpenCV stores it as 0–179 (degrees halved, so the full circle fits in a uint8).

Red sits on the seam. There is no pair lower ≤ upper that selects it, so the convention is that lower > upper means "wrap through zero," and the test flips from AND to OR. That single operator swap is the entire wraparound implementation.

The cast to int32 is defensive: comparing uint8 pixels against a bound like -1 or 300 would otherwise involve dtype promotion rules you do not want to reason about mid-mask.

The whole file converges here. Reverse the column axis (section 02), promote to float so the multiply does not wrap (section 04), scale channel 0 only, then round → clip → cast (Rule 03) back to the uint8 the video encoder requires.

The .astype(np.float64) also produces the copy, so out[:, :, 0] *= 0.65 is safe to write in place — it is mutating a new array, never the decoded frame.

Because it is pure and stateless, the same function drives every frame of a1_transformed.mp4 and can be unit-tested on a single hand-made 2×2 array.

09

Sharp edges

Nothing here fails the public tests. These are the places where the code and its description have drifted slightly, or where a future edit could go wrong.

The loop calls into NumPy per pixelbrighten_loop:130

np.rint inside a Python loop pays NumPy's scalar-dispatch cost on every element. Python's built-in round() is also half-to-even, so it would give byte-identical results far faster. For a timing experiment that exists to show how slow per-pixel Python is, keeping np.rint is defensible — but if you cite the ratio in the analysis, be clear that part of it is call overhead, not just the loop.

Half-coerced bounds check_check_rectangle:34–39

The sign check calls int(top), but the bounds check uses top + height unconverted. Integer inputs behave identically either way; a float like top=1.5 would slip past the guard and raise a less clear IndexError from the slice instead.

A guard named for the wrong color spacehsv_rule:192

hsv_rule validates its input with _check_rgb. The check itself is correct — it only asserts (H, W, 3) — but the name says RGB while the argument is HSV. _check_three_channel would say what it actually means.

Docstring promises a viewflip_horizontal:50

"Return a horizontally flipped view or copy" — it always returns a copy. Correct behavior, imprecise wording, and the kind of thing a grader reading docstrings will notice.

fill_value is uncheckedcontact_sheet:105

np.full(shape, fill_value, dtype=np.uint8) will happily take 300 and wrap it. The columns and dtype arguments are validated; this one is not.
